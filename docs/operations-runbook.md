# Operations failure and recovery runbook

This is the bounded operating procedure for the local candidate. It separates detection and safe next actions from tenant acceptance evidence. The installed runtime owns queue state and recovery; the MCP host is an interface and may be unavailable without stopping autonomous maintenance. No procedure below treats a timeout, missing output, or persisted `Running` record as proof of success.

| Scenario | Detection | Safe recovery path | Do not do | Tenant evidence |
|---|---|---|---|---|
| Missing connection or binding | Read-only installation/deployment plan reports a missing or invalid binding, connection mapping, or API registration | Leave flows Draft, preserve the plan/journal, repair the approved development connection mapping, create a fresh plan hash, and rerun preflight | Do not pass a connection token in a tool argument, reuse a stale plan, or activate partially checked flows | Required |
| Licensing or capacity failure | Preflight/manual prerequisite remains unknown or the platform returns a licensing/capacity denial | Stop activation and escalation; record the exact bounded fault and request budget; resume only after an approved capacity check | Do not busy-poll, multiply retries, or claim a local simulator rate as a platform limit | Required |
| Owner departure or permission loss | `WhoAmI`, role, queue-grant, or connection-owner check fails | Stop mutations, retain durable evidence, use an approved administrator to transfer ownership/connection responsibility, then rerun identity and preflight checks | Do not broaden roles or substitute the operator identity silently | Required |
| Environment copy or target mismatch | Organization ID, environment URL, or development-class binding differs from the reviewed plan | Reject before mutation, create a new explicit development binding, and review the target from the beginning | Do not reuse a plan, journal, queue ID, or credentials from another environment | Required |
| Failed or interrupted import | Package/journal status is `Failed`, `LaunchFailed`, or `Running` after the worker is confirmed terminated | Preserve logs and the target state; reconcile only the recorded partial deployment, remove only its lock, and create a new reviewed plan/request; use a forward fix or approved environment recovery | Do not silently resume, uninstall/reinstall a data-bearing solution, or call a launch result complete | Required |
| MCP host unavailable | Agent session ends or the MCP transport is disconnected | Allow installed watchdog/coordinator/sender flows to continue; inspect durable status later using the documented operator path | Do not assume the MCP session owns processing or invent an evidence result | Runtime/tenant observation |
| Worker timeout or lost response | Status is unknown, lease expires, or an external response was discarded | Treat the outcome as review-required; reconcile the stable source/business identity, then use an authorized current-version retry only when effects are verified safe | Do not retry blindly, call business `Fail` after an unknown completion, or infer success from a timeout | Required for external effects |
| Backlog, missed wake-up, or expired attempt | Bounded health page, maintenance receipt, stale lease, or review-required item | Pause acquisition when a cutover requires it, preserve incoming events, run bounded maintenance, inspect active/review-held work, and advance only with durable evidence | Do not drain by deleting source events, skip the native state owner, or run an unbounded sweep | Required for native/scheduler behavior |
| Core environment outage | No trusted read or mutation path to the same environment | Use the separately operated monitoring/escalation path and wait for service recovery; preserve local operator notes without claiming tenant state | Core cannot reliably notify through the unavailable environment; do not report self-notification as a guarantee | Required |

## Evidence discipline

Record the commit/package hash, environment and platform version, identity/role, case/run/request/item/attempt identifiers, expected and actual outcome, and an authorized evidence reference. Keep mailbox content, credentials, access tokens, headers and raw customer payloads out of published evidence. A failed, denied, missing, timed-out or inconclusive observation remains incomplete.

The local candidate proves bounded input validation, request replay, durable deployment journaling, stale/active ownership checks, retention tombstones, redacted status views and the procedures above. It does not prove licensing, capacity, managed import, environment-copy behavior, separate-user native privileges, connector delivery, or production recovery. Those remain open acceptance work in [P7-05](https://github.com/EricLott/Power-Automate-Work-Queue-MCP/issues/68), [P7-06](https://github.com/EricLott/Power-Automate-Work-Queue-MCP/issues/69), and the linked gates.
