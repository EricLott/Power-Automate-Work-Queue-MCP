# Bounded retention and maintenance proof

Queue policy contains independently validated windows for payloads, receipts/replay, attempts, errors and test evidence. Retention now applies bounded, cursor-driven cleanup for each class: old terminal payloads are replaced with `{}`, old command receipts become `ReplayExpired` tombstones, old non-current terminal attempts may be deleted, old intake-failure rows may be deleted when their historical delivery is not active, and terminal test-run evidence is deleted only when every referenced fixture is safely terminal and all expected evidence rows are present.

Retention runs inside the runtime command boundary, uses bounded native and companion-table pages, and returns redacted counts for redactions, tombstones, purged attempts, purged errors, purged evidence rows and protected rows. Attempt and test evidence cleanup uses the effective destination snapshot captured with the attempt, so a later queue-policy destination change cannot hide an active delivery. New intake-failure rows capture the same snapshot; legacy rows without it are retained conservatively. Optimistic row-version deletes fail closed on concurrent changes. It preserves active attempts, queued or Processing items, review-held items, ordinary `OnHold` work, current-attempt snapshots, incomplete evidence and active notification deliveries. A concurrent or stale policy update is rejected by the existing queue-policy version check. Invalid or out-of-range retention windows fail closed as `POLICY_INVALID`.

Local regression coverage is in `tests/runtime/RetentionPolicyTests.cs`, `tests/runtime/CancellationTests.cs`, and the existing cleanup/CAS tests. It verifies independent windows, replay tombstones, old attempt/error cleanup, historical-destination and legacy-row protection, active-delivery protection, terminal evidence cleanup, deduplication identity, review holds, active work and cancellation preservation. A real tenant run is still required for native aged-row behavior, scheduler execution, storage cost, and managed-release compatibility; P7-04 remains open until those acceptance criteria are observed.

The authorized development tenant now passes a bounded aged-retention proof on an isolated synthetic queue. The fixture creates 366-day-old native rows and companion evidence, uses the supported `PrepareAcquire` → native `Microsoft.Dynamics.CRM.Dequeue` → `ResolveAcquire` handoff, then completes one row and business-fails the review row. Retention redacts one terminal payload, tombstones one receipt as `ReplayExpired`, purges three evidence rows, preserves the review payload and returns `ReviewRequired`.
