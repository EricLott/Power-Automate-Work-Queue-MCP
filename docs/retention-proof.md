# Bounded retention and maintenance proof

Queue policy contains independently validated windows for payloads, receipts/replay, attempts, errors and test evidence. Retention now applies bounded, cursor-driven cleanup for each class: old terminal payloads are replaced with `{}`, old command receipts become `ReplayExpired` tombstones, old non-current terminal attempts may be deleted, old intake-failure rows may be deleted when their delivery is not active, and terminal test-run evidence is deleted only when every referenced fixture is safely terminal and all expected evidence rows are present.

Retention runs inside the runtime command boundary, uses bounded native and companion-table pages, and returns redacted counts for redactions, tombstones, purged attempts, purged errors, purged evidence rows and protected rows. Optimistic row-version deletes fail closed on concurrent changes. It preserves active attempts, queued or Processing items, review-held items, ordinary `OnHold` work, current-attempt snapshots, incomplete evidence and active notification deliveries. A concurrent or stale policy update is rejected by the existing queue-policy version check. Invalid or out-of-range retention windows fail closed as `POLICY_INVALID`.

Local regression coverage is in `tests/runtime/RetentionPolicyTests.cs`, `tests/runtime/CancellationTests.cs`, and the existing cleanup/CAS tests. It verifies independent windows, replay tombstones, old attempt/error cleanup, active-delivery protection, terminal evidence cleanup, deduplication identity, review holds, active work and cancellation preservation. A real tenant run is still required for native aged-row behavior, scheduler execution, storage cost, and managed-release compatibility; P7-04 remains open until those acceptance criteria are observed.
