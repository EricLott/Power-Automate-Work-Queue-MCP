## Evidence requirements

For a live run record the commit/package hash, environment and platform version, identity/role, case ID, request/run/item/attempt IDs, expected outcome, actual outcome, and an authorized evidence reference. Redact mailbox content and credentials. A failure, permission denial, missing output, or timeout cannot be turned into a pass. Preserve the original expected results when repeating AI evaluations.

At the initial local-build checkpoint, unresolved tenant questions included: dequeue transaction boundaries and response shape; queue state transitions; role and team ownership behavior; first import metadata; prompt/connector binding; child flow deployment; and managed upgrade behavior. Subsequent linked proofs resolve selected questions; the current gate snapshot identifies remaining acceptance work. The [first import runbook](first-import.md) orders experiments before production activation.
